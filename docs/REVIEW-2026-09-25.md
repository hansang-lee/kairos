## 1. Fix now

### 1.1 Dashboard is on the LAN with no authentication — `[x] fixed`

`scripts/dashboard_server.py:171` binds `0.0.0.0:8800`. `/live/portfolio.json` serves
the account balance and holdings with no auth. At review time the service was
`active`, listening on the machine's LAN address. It is a private range, so this is
LAN exposure rather than internet exposure, but it contradicts the standing rule
that the dashboard is never exposed without auth.

Fix: bind `127.0.0.1`. The Telegram bot already covers "check from my phone".

### 1.2 CI does not run the tests — `[x] fixed`

`.github/workflows/` holds only `macro-report.yml`, a daily cron that commits a macro
report. The 181 tests run nowhere on push. A local run that was forgotten lands
broken.

Fix: a workflow that configures, builds, runs `kairos_tests`, and runs
`clang-format --dry-run --Werror` over the tracked sources.

### 1.3 Holiday calendar is entirely projected, with no check against reality — `[x] fixed`

Every 2026 entry in `config/krx_holidays.json` is `(projected)`, computed from the
lunar calendar because the paper account cannot call the KIS holiday API
(`EGW02006`). Nothing confirms a projection after the fact. Both directions are
costly: a trading day marked closed silently skips signals; a holiday marked open
places orders at yesterday's close. `src/data/krx_calendar.cpp` also fails open —
with no file it treats only weekends as closed.

Fix: after each run, compare the projection against whether KIS produced a bar for
that date, and alert on disagreement. This is what was done by hand on 09-24.

## 2. Defects

### 2.1 Journal reference price can be yesterday's close — `[x] fixed`

`app/trader.cpp:355` sets `price = data->close.back()`. When KIS has not yet
published today's bar, that is yesterday's close, while the order fills at today's
market. The order/fill price gap is meant to measure slippage; on those days it
measures a day's move instead. The reference should be a live quote.

### 2.2 Unknown-parameter warning covers 3 of 24 strategy types — `[x] fixed`

`src/strategy/strategy_factory.cpp`: `warnUnknownParams` is applied to `bollinger`,
`aroon` and `relative_momentum` only. `params.value(key, default)` silently returns
the default for a misspelled key, which is the bug that invalidated a whole
parameter sweep (`std_dev` vs `std_devs`). Twenty-one types still swallow typos.

Fix: apply it to every type, or have the factory reject unknown keys outright.

### 2.3 A rejected order consumes the daily order cap — `[ ] open (design)`

`src/trade/signal_executor.cpp:249-251` calls `recordOrder()` unconditionally after
`placeOrder`. An order KIS rejects outright counts against `max_orders_per_day`. An
indeterminate order (response lost) should count, since it may exist; an explicit
rejection arguably should not. Harmless at the current 20/day with three profiles;
the intent is not written down.

### 2.4 Token cache and `.env` resolve relative to the working directory — `[x] fixed`

`src/broker/kis_auth.cpp` uses `cache/kis_token_paper.json`; `include/common/util.hpp`
`envValue` defaults to `.env`. Every other piece of state uses `resolveFromExe`.
Under systemd `WorkingDirectory` this is fine; run by hand from elsewhere, each
process requests a fresh token. KIS limits token issuance, so a manual `doctor` at
15:15 can starve the trader's token request. A `초당 거래건수 초과` was observed during
back-to-back manual runs on 09-24.

### 2.5 `RiskGuard::check()` calls `observe()` again — `[x] not a defect`

The trader observes once per cycle; the executor's `check()` observes again. On
re-reading `observe()` for the fix: it writes only when something changed, and on
the second call with the same balance nothing has, so there is no redundant write.
The second call is a no-op. The review's claim of "one redundant state write" was
wrong; closed without a code change.

## 3. Structure

### Strengths

- Three-way config split (`strategies.json` / `universe*.json` / `live.json`): the
  backtest and the trader reference one definition. Both backtest↔live mismatches
  found this session were code-side, not config-side, because of this.
- Append-only JSONL journal with a flush per line.
- Operational hardening is real and each piece carries the incident that motivated
  it: flock process lock, interruptible sleep, curl timeouts, the indeterminate
  order state, whole-share sizing, entry/exit tranches.
- Comment quality. Comments say why, and most say what went wrong before. The code
  reads as a lab notebook, which is the most valuable thing here for whoever picks
  it up next.

### 3.1 No `IBroker` — `[x] fixed`

`include/data/idata_provider.hpp` exists for quotes. Nothing equivalent exists for
orders: `KisTrader` is static functions called directly from `SignalExecutor`. Two
consequences. The Meritz migration cannot happen without editing the executor. And
the executor's `live_ == true` branch has never been unit-tested — no test calls
`KisTrader::` — because there is no seam to put a fake behind. That branch runs for
the first time on 09-29.

### 3.2 Decision logic lives in `app/` — `[ ] open`

`app/` is 6.1k lines across 28 binaries with zero tests. `app/trader.cpp` (455 lines)
decides which bar to evaluate, whether a profile is due, whether the market is
open, and whether to send the summary — all inside `main()`. Extract into
`trade/session` and the existing test framework covers it as-is.

### 3.3 Eight copies of the KST date helper — `[x] fixed`

`app/trader.cpp` (2), `app/doctor.cpp` (2), `app/bot.cpp`, `app/scalp_backtest.cpp`,
`src/data/bar_recorder.cpp`, `src/trade/risk_guard.cpp`, `src/trade/trade_journal.cpp`.
All use the same UTC+9-then-gmtime approach and agree today. One
`common/kst_time.hpp`.

### 3.4 `app/` mixes product with research — `[ ] open`

Product: `trader`, `bot`, `doctor`, `portfolio_report`, `fetch_universe`. The other
23 are research tools. `qld_dca_backtest` is superseded by `dca_backtest`;
`leverage_study` and `beat_benchmark` overlap substantially. Split into
`app/research/` or prune.
